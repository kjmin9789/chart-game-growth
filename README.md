# 차트게임 시드 매출 성장 기획

알파스퀘어 차트게임의 시드 매출을 높이기 위한 개인 비공개 기획 저장소다. 실제 서비스 구현은 알파스퀘어 조직 저장소에서 진행한다.

시드 매출은 과거 월 200만 원까지 발생했던 항목으로 회복·성장 가능성이 있다고 본다. 과거 수치는 해당 월을 추가 확인해야 하며, 최근 결제액과 기간은 [결제 현황](research/2026-11-24-GA와-시드결제-기준현황.md)에 정리했다. 현재는 첫 실험을 고르기 위한 원인 조사 단계다.

## 폴더와 운영 단위

**문제 → 후보안 비교 → 실험 → 태스크 → 결과**로 연결한다. 스프린트에는 이번에 진행할 작업을 모은다.

```text
problems/P번호-문제명.md               # 문제와 후보안 비교
experiments/E번호-실험명/
  README.md                          # 가설·설계·결과
  tasks/T번호-작업명.md               # 실험에 소속된 태스크 카드
sprints/S번호.md                     # 목표·태스크 링크·회고
request/YYMMDD-태스크명.md            # 개발 전달용 상세 요구사항
```

실험·태스크·스프린트는 실제 작업을 시작할 때 만든다. 문제 정의에는 현재 가이드를 사용한다.

## 문서별 필수 항목

- **문제:** 공통 배경, 대상과 상황, 관찰한 문제, 영향, 해결할 이유, 문제 정의, 원인 가설과 대응 후보. 성공 기준·확인 시점·실행 방법은 개별 실험에서 정한다.
- **실험:** 상위 문제, 상태, 대상·제외 조건, 가설, 변경 내용·대조군·배정 방법, 지표·기간·표본·판정 기준, 태스크 링크, 결과와 다음 결정. 실행 후 설계를 바꾸면 변경 시점과 이유를 남긴다.
- **스프린트:** 이번에 답할 질문, 문제·실험·태스크 링크, 회고와 다음 작업.

태스크 카드는 아래 양식을 사용한다. T번호는 저장소 전체에서 중복 없이 부여한다.

```markdown
# T번호 작업명

- 상위 실험: ../README.md
- 스프린트:
- 상태: 할 일
- 담당자: 미정
- 선행 태스크:

## 목적과 작업 내용

## 완료 기준

- [ ] 확인 가능한 완료 조건

## 산출물과 진행 기록

요구사항·Figma·구현 PR 링크, 막힌 이유와 필요한 조치.
```

## 관리 규칙

- 태스크 상태는 **할 일 → 진행 중 → 검토 중 → 완료**, 별도로 **보류**를 둔다. 담당자·상태·완료 기준은 카드에서만 관리한다.
- 실험 상태는 **설계 중 → 실행 준비 → 진행 중 → 분석 중 → 종료**, 별도로 **보류**를 둔다. 태스크 완료와 실험 결과 판정을 구분한다.
- 스프린트가 바뀌어도 실험·태스크 파일을 옮기지 않고 링크로 연결한다. 공통 작업도 복제하지 않고 기존 카드·산출물을 참조한다.
- 초기 조사는 관련 문제 문서에 정리한다. 후속 실험의 추가 작업은 새 카드로 만들고 이전 결과를 연결한다.
- 개발 요구사항은 [작성 규칙](TASK-WRITING.md)을 따르고, 실제 조직 저장소의 이슈·PR을 연결한다.
